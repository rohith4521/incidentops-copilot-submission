# Verification Evidence

This document separates measured repository evidence from architectural claims.

## Automated gates

The repository continuously verifies:

- Ruff linting
- Mypy type checking
- pip-audit dependency auditing
- pytest execution
- pytest-cov coverage measurement
- Docker image build
- TypeScript/Vite production build
- frontend production-artifact smoke validation
- npm audit
- CodeQL analysis
- pull-request dependency review

## Coverage

Coverage is measured by CI with:

~~~text
pytest -v --cov=app --cov-report=term-missing --cov-report=xml
~~~

The repository intentionally does not publish a target percentage until the measured baseline is reviewed. A coverage number should only be promoted into README/project claims when it is generated by the current codebase.

## Frontend smoke validation

After the Vite build, a dependency-free Node smoke test verifies that:

1. dist/index.html exists.
2. The output is a valid HTML document.
3. Referenced JS/CSS assets exist.
4. At least one production JavaScript bundle was emitted.

This is a build-artifact integrity check, not a substitute for browser-level behavioral or accessibility testing.

## Evidence discipline

Passing CI proves that the current automated contracts pass. It does not prove production-scale availability, security perfection, real-world MTTR reduction or independent security certification.
